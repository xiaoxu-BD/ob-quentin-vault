# 计算机网络

# OSI七层网络模型

* 应用层 	 为计算机用户提供服务
* 表示层	 数据处理
* 会话层	管理 应用程序之间的会话
* 传输层  为两台主机进程之间的通信提供通用的数据传输服务
* 网络层    路由寻址
* 数据链路层 -> 帧编码和误差纠正控制
* 物理层  -> 透明传输比特流

# TCP/IP四层网络模型:

# 访问网页全过程?

1. 在浏览器中输入指定网页的URL
2. 浏览器通过DNS协议,获取域名对应的IP地址
3. 浏览器根据IP地址和端口号,像目标服务器发起一个TCP连接请求
4. 浏览器在TCP连接上,向服务器发送一个HTTP请求报文,请求获取网页的内容
5. 服务器收到HTPP请求报文后,处理请求,并返回HTTP响应报文给浏览器
6. 服务器收到一个HTTP请求报文后,解析响应体中的HTML代码,渲染网页的结构和样式
7. 在不需要的和服务器进行通信,可以主动关闭TCP连接,或者等待服务器的关闭请求.

# 三次握手和四次挥手

**三次握手:**

1. 客户端向服务端发送SYN,表示要建立连接
2. 服务端向客户端发送SYN+ACK,表示服务端已经收到客户端的请求,并且同意建立请求
3. 客户端向服务器发送ACK,表示<font style="color:rgb(44, 44, 54);">确保服务端知道客户端已经收到了它的响应。至此，连接建立完成，双方可以开始通信。</font>

**<font style="color:rgb(44, 44, 54);">四次挥手:</font>**

1. 客户端向服务端发送FIN,表示客户端没有更多的数据需要发送,此时客户端进入了`FIN-WATI-1`状态
2. 服务端收到客户端的FIN后,会向客户端发送ACK,服务端进入`CLOSE-WAIT`状态,表示客户端到服务端的连接已经关闭,但服务端还可以继续向客户端发送数据,客户端收到服务端的ACK后,进入`FIN-WAIT-2`状态.
3. 如果服务端没有更多的数据需要发送给客户端,则服务端向客户端发送FIN,表示进入最后确认状态,服务器进入`LAST-ACK`,而客户端进入`TIME-WAIT`状态.
4. 客户端接收到服务端的FIN后,客户端向服务器方法ACK,表示确认关闭,客户端仍然处于TIME-WAIT状态,等待2MSL最大生存时间的两倍,客户端才会真正的关闭连接并进入`CLOSED`状态,服务端在接收到客户端的ACK后,会立即进入到`CLOSED`状态
